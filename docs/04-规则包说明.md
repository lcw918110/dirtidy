# dirtidy — 规则包说明

## 1. 内置包

| 包 | 文件 | 用途 |
|----|------|------|
| default | `src/dirtidy/rules/packs/default.yaml` | 通用高置信清理 |
| server_workspace | `src/dirtidy/rules/packs/server_workspace.yaml` | 服务器/交接类工作区（含日志目录、target/vendor 等） |

可复制修改后用 `--rules` 指定。`server_workspace` 通过 `extends: default` 继承全部基础规则。

## 2. 置信分层

| action | 行为 |
|--------|------|
| `protect` | **最高优先级**。命中路径（目录含整棵子树）永不自动隔离，也不进候选，只在 `protection.json` / `audit.md` 里登记 |
| `auto_quarantine` | `apply-rules` / `--apply` 时移入隔离区 |
| `candidate_only` | 只进 `candidates.json`，待人工或决策 |

### 2.1 保护（protect）语义

- 判定**不受规则书写顺序影响**：把 `auto_quarantine` 写在 `protect` 前面也不会误删，
  实现上对每条规则命中的路径单独复核保护清单，而不是先到先得。
- `dir_name` 命中的是**整棵子树**：`.git` 被保护 ⇒ `.git/objects/...` 不可能被自动搬走。
- 命中保护 = 既不隔离、也不进候选。原因：候选区是给人点「隔离」的，把密钥/版本库放进去
  等于给了误操作入口；但审计里逐条列出「哪条规则想动它、被哪条保护规则挡下」，不会静默吞掉。
- 隔离阶段会**再复核一次**：`apply-rules` 在真正搬文件前用当前生效的保护清单重查
  `pending_auto_hits`，防止 pending 列表被改过或规则包换过之后绕过保护。
- 内置清单写在 `src/dirtidy/rules/protect.py`，**不可被规则包关掉**；规则包只能追加自己的 `protect` 规则。
- 追加方式：`dirtidy scan <root> --protect rel/path`（可重复），等价于给该路径及其子树加一条 protect 规则。

## 3.1 匹配类型

| type | 字段 | 说明 |
|------|------|------|
| `dir_name` | `names` | 目录名精确匹配 |
| `file_name` | `names` | 文件名精确匹配，仅文件 |
| `name_glob` | `globs`（可配 `is_dir: true/false`） | basename 通配匹配 |
| `suffix` | `suffixes` | 扩展名匹配，仅文件 |
| `empty_dir` | — | 空目录（以文件系统为准） |
| `empty_file` | — | 0 字节且无读取错误的文件 |
| `path_glob` | `patterns` | 相对路径通配匹配 |

## 3.2 条件块 `when`

| 字段 | 说明 |
|------|------|
| `min_age_days` / `max_age_days` | 按 mtime 判断「多久没动过」；mtime 缺失时保守判为不命中 |
| `min_size_bytes` / `max_size_bytes` | **仅对文件生效**（目录大小不聚合） |
| `under` / `not_under` | 路径前缀白名单 / 黑名单 |
| `min_depth` / `max_depth` | 相对根目录的层级 |
| `require` | 守卫列表，目前支持 `source_free`：目录子树内没有源码/构建定义文件才命中 |

`when` 的意义就是「不误删」：单靠目录名判断太糙，加上「多久没动」「多大」「里面还有没有源码」才敢自动搬。

规则包在加载时即校验：未知 `action` / `match.type` / `when` 字段、缺必填字段、id 重复都会直接报错，
不会等到扫完几百万文件才发现笔误。

## 4. 解压残留算法（非 YAML 硬编码逻辑）

1. 对每个归档文件，流式读取成员内容，计算 `sha256`（跳过目录成员）。
2. 在同一扫描根下，收集已计算内容 hash 的文件集合。
3. 若归档内「可哈希成员」中，命中磁盘文件 hash 的比例 ≥ 阈值（默认 0.8，且命中数 ≥ 1），则将该归档标为候选 `archive_extracted`。
4. 加密或无法读取的归档：标 `archive_review`（rule_id=`archive_unreadable`），不自动隔离。加密 zip 抛出的 `NotImplementedError` 也归为不可读。

**禁止**用「同名解压目录」作为充分条件。

## 5. 重复文件

同 `sha256` 且文件数 ≥ 2 → `duplicate_group` 候选；保留策略仅人工。

## 6. 隔离后的空目录

规则包里 `empty_dir` 为 `auto_quarantine` 时，`apply` 之后会多轮把「子项搬走后才空」的父目录一并隔离（最多 8 轮）。目标根本身与 `.dirtidy` 不处理。

## 7. hash 缓存

非 quick 扫描把文件 `path + size + mtime + sha256` 记在目标下 `.dirtidy/hash_cache.json`。未改动的文件下次不再读内容。扫描中断后下次会从未命中缓存的文件继续算，已算过的直接复用。
