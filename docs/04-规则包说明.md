# dirtidy — 规则包说明

## 1. 内置包

| 包 | 文件 | 用途 |
|----|------|------|
| default | `configs/rules/default.yaml` | 通用高置信清理 |
| server_workspace | `configs/rules/server_workspace.yaml` | 服务器/交接类工作区（含缓存、日志等） |

可复制修改后用 `--rules` 指定。

## 2. 置信分层

| action | 行为 |
|--------|------|
| `auto_quarantine` | `apply-rules` 时移入隔离区 |
| `candidate_only` | 只进 `candidates.json`，待人工或决策 |

## 3. 内置规则 ID（default）

| id | 匹配 | action |
|----|------|--------|
| dep_node_modules | 目录名 `node_modules` | auto |
| dep_venv | 目录名 `.venv`/`venv` | auto |
| dep_pycache | 目录名 `__pycache__` | auto |
| dep_m2_cache | 目录名 `.m2` | auto |
| dep_target_java | 目录名 `target`（可关） | candidate（避免误伤） |
| empty_dir | 空目录 | auto |
| empty_file | 0 字节文件 | candidate |
| log_suffix | `*.log` / `*.log.*` | auto |
| installer_suffix | `.dmg/.msi/.deb/.rpm/.exe`(安装类，可配) | candidate |

`server_workspace` 在 default 基础上收紧日志目录名、扩大缓存名列表。

## 4. 解压残留算法（非 YAML 硬编码逻辑）

1. 对每个归档文件，流式读取成员内容，计算 `sha256`（跳过目录成员）。
2. 在同一扫描根下，收集已计算内容 hash 的文件集合。
3. 若归档内「可哈希成员」中，命中磁盘文件 hash 的比例 ≥ 阈值（默认 0.8，且命中数 ≥ 1），则将该归档标为候选 `archive_extracted`。
4. 加密或无法读取的归档：标 `review`，不自动隔离。

**禁止**用「同名解压目录」作为充分条件。

## 5. 重复文件

同 `sha256` 且文件数 ≥ 2 → `duplicate_group` 候选；保留策略仅人工。

## 6. 隔离后的空目录

规则包里 `empty_dir` 为 `auto_quarantine` 时，`apply` 之后会多轮把「子项搬走后才空」的父目录一并隔离（最多 8 轮）。目标根本身与 `.dirtidy` 不处理。

## 7. hash 缓存

非 quick 扫描把文件 `path + size + mtime + sha256` 记在目标下 `.dirtidy/hash_cache.json`。未改动的文件下次不再读内容。扫描中断后下次会从未命中缓存的文件继续算，已算过的直接复用。
