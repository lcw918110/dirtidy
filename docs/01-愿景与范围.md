# dirtidy — 愿景与范围

## 1. 产品定位

`dirtidy` 是跨平台（macOS / Linux / Windows）的**本地目录整理工具**：用可配置规则清理高置信无用物，对残留文件做模型辅助分析，并由人工在可视化界面终审「留 / 隔离 / 归类」。

统一底层引擎；界面为 CLI 与本地 Web，不绑定单一业务场景。

它是**单机、单用户的后台程序**：可以无人值守地长期跑（`watch` 定时扫描、`desktop` 常驻起服务），
也可以被中断后重跑。因此稳定性与性能按**后台程序**的标准要求，而不是交互式工具那一套：
不因单个坏输入而整体失败、被中断后不留下损坏状态、长时间运行不无限增长、出问题查得到。
设计与取舍见 [08-稳定性与性能设计.md](08-稳定性与性能设计.md)。

## 2. 典型场景（示例，非产品边界）

- 服务器或工作区长期堆积的依赖缓存、日志、安装包、解压残留压缩包、重复文件、空目录
- 交接或归档前，对「说不清」的大目录做可审计清理与归类建议
- 本机项目目录的周期性整理（交给 `watch` 定期跑）

## 3. 干系人

| 角色 | 诉求 |
|------|------|
| 运维 / 管理员 | 在服务器上用 CLI 安全扫描与隔离，可回放审计 |
| 业务负责人 | 在本机 Web 上确认残留文件的去留与归类 |
| 工具维护者 | YAML 规则包与模型配置可扩展 |

## 4. MVP 范围（第一期）

**做：**

- 扫描指定根目录，产出 inventory 与审计
- YAML 规则包：高置信项默认进隔离区（quarantine）
- 解压残留（成员内容 hash 对照）、重复文件：默认仅候选，重复由人工选留
- 旁路压缩包：基于内容判定后再标候选
- 可配置 OpenAI 兼容 API 与 Ollama；外发默认安全摘要
- CLI 全流程 + 本地 FastAPI Web 审阅与决策回写

**不做：**

- 无确认的自动彻底删除

> 原「不做」清单里的桌面原生壳与文件夹定时监视，已在第二期以**受限形态**立项（见 §4.1）：
> 桌面壳只做薄壳启动器，定时监视只扫描不执行。

## 4.1 第二期范围（形态受限）

第一期收口后确认要做，但每一项都带明确的形态约束——**形态本身就是需求的一部分**，
不是实现细节：

| 项 | 形态 | 为什么只能是这个形态 |
|----|------|----------------------|
| 桌面壳 | **薄壳启动器**：一键起本地服务并打开浏览器；托盘图标为可选增强 | 干系人含非技术用户，开终端是主要门槛。但不做 Electron/Tauri：打包签名、自动更新成本高一个数量级，且此后每次改动都要维护两份前端 |
| 定时监视 | **只扫描 + 通知**：定期扫描出预览并提醒，**绝不自动搬文件** | 与「不误删、执行必须人工」的核心承诺直接冲突。自动执行等于把前几轮加固的保护判定全部作废 |
| 扫描内存 | **中间路线**：单条瘦身（去掉 `suffix` 字段、按需 `suffix_of(path)` 现算），不重写扫描管道 | 500 万条实测约 1.55 GB，在 2 GB 上限内；全流程流式化要重写刚做完安全加固的核心链路，风险收益比差 |
