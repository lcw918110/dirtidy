# dirtidy 使用手册

先用一个可恢复的测试目录走完「扫描 → 审阅 → 执行 → 还原」，确认符合预期后，再处理实际目录。首次使用读第 1 节即可；Cursor 状态库清理单独见第 2.4 节，完整参数放在第 3 节供查阅。

## 1. 第一次使用：扫描、确认、还原

dirtidy 是单机、单用户的目录整理工具。规则找出可隔离项，模型可辅助分析剩余候选，最后由你决定是否执行。不接模型也能完成整个目录整理流程。

### 1.1 安装并检查

在仓库目录打开终端，需要 Python 3.11 或更高版本：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
source .venv/bin/activate
dirtidy --version
```

能看到版本号后再继续。以下命令都假设虚拟环境已激活；否则将 `dirtidy` 换为 `.venv/bin/dirtidy`。Windows 的激活命令为 `.venv\Scripts\Activate.ps1`，可执行文件为 `.venv\Scripts\dirtidy.exe`。

### 1.2 打开测试目录

把 `/path/to/root` 换成你的测试目录绝对路径，路径含空格时加双引号。

```bash
dirtidy start /path/to/root
```

首次运行会扫描目录并打开本地网页，**不会搬动待整理文件**。扫描记录写入目标目录的 `.dirtidy/`。已有扫描结果时直接打开网页；要重扫可运行：

```bash
dirtidy start /path/to/root --rescan
```

网页打开后，先核对目标目录是否正确，再查看本轮扫描结果。一次扫描称为一个 **run**；页面上显示的完整 `run_id` 用于后面的命令行操作。

### 1.3 审阅：确定哪些不动

进入「审阅」页，按下面顺序看：

1. **待自动隔离**：这些是规则选中的项目，还没有搬走。看路径、占用和「删了怎么办」，不想动的勾选「保留」。
2. **候选 / 建议**：重复文件、归档残留和其他待判断项。默认保留不动；你可以逐条选择保留、隔离或归档。模型建议不会自行生效。
3. **受保护清单**：检查需要保留的凭据、版本控制目录等是否在列。对某条不理解，点路径旁的「为什么？」。

**筛选和分页只影响显示，不缩小执行范围。** 待自动隔离列表每页最多显示 100 项，执行仍按全部命中计算；不处理的项目必须明确设为保留。待自动隔离的全选保留作用于全部命中；候选表的全选只选择当前页，跨页已选项目会保留。

候选表可组合路径、规则类型、模型建议和当前决策筛选；「选择全部筛选结果」会跨页追加勾选，清空已选可重新开始。对已选项可统一设置决策，或采纳其中的模型建议：已有决策、无建议及缺少归档目标的项会跳过。勾选只改变选择，设置或采纳只改变决策，不搬文件；实际执行前仍需预览并确认。批量设为归档时，目标默认按 `archive/<原相对路径>` 落位，同名文件不会互相顶掉。规则候选统一显示「需要你判断」，请结合判断依据和恢复说明，不能把这个标签当成清理许可。

### 1.4 执行：先预览，再确认

进入「执行」页，核对规则隔离与候选决策各自的清单，先点预览，再确认执行。预览中应能看到实际将搬移、保留或被保护拦下的项目。

| 选择 | 执行后的位置 | 能否在工具内还原 |
|---|---|---|
| 保留 | 原位置 | 无需还原 |
| 隔离 | `.dirtidy/quarantine/<run_id>/` | 可以，前提是隔离副本仍在 |
| 归档 | 你指定的根目录内相对路径（批量时默认 `archive/<原相对路径>`） | 不通过隔离区还原；到归档位置找回，记录见 `runs/<run_id>/archive_manifest.json` |
| 彻底删除 / 已开启的直删规则 | 文件物理删除 | 不可以 |

归档同样受保护清单约束：`.env`、`.git` 等受保护路径即使被标成归档也不会搬走，预览里会列为被拦下。动作写错时该条会进「跳过」并说明原因，不会静默消失。

首次验证请保持「规则」页的直删开关关闭。默认没有开启直删；若以前开过，后续网页和命令行执行都会沿用该设置。

执行后检查：原位置的目标已移走，「隔离区」出现对应记录；勾选保留的项目仍在原处。隔离只是换位置，**不会释放这份文件占用的空间**。

### 1.5 还原：验证能回到原位

进入「隔离区」，选一条刚隔离的记录点「还原」，核对文件回到原路径且内容可打开。原路径已存在同名文件时，程序跳过，不覆盖。

手动验证到这里就可以结束。只有确定隔离副本不再需要时，才使用「彻底删除」释放空间；不要把它当成验证流程的必做步骤。

关闭服务：在启动它的终端按 `Ctrl-C`；启用了托盘时也可从托盘退出。只关闭浏览器页面不会停止服务。

## 2. 按需要完成其他任务

### 2.1 不开网页，直接用命令行

下面每一步单独执行。`<run_id>` 要替换为扫描输出的实际值，不能原样输入尖括号占位符。

先扫描，再解释某个相对路径：

```bash
dirtidy scan /path/to/root
dirtidy explain /path/to/root node_modules
```

扫描会生成 run 记录，不移动待整理文件。解释命令显示保护、规则及条件的判定。额外保护路径可在扫描时指定，例如 `--protect keep`；切换规则包时，解释也要使用同一个 `--rules`。

预览规则隔离，并保留指定项目：

```bash
dirtidy apply-rules /path/to/root <run_id> --dry-run --keep logs/keep-me.log
```

确认清单后，去掉 `--dry-run`，保留相同的 `--keep` 参数：

```bash
dirtidy apply-rules /path/to/root <run_id> --keep logs/keep-me.log
```

`apply-rules` 不加 `--dry-run` 就会执行，不需要另加 `--apply`。它也会读取此前开启的直删设置，执行前应在网页「规则」页核对。

候选决策可以在网页保存，也可准备一个 JSON 数组文件，例如：

```json
[
  {"path": "notes.txt", "action": "keep"},
  {"path": "old-copy.txt", "action": "quarantine"},
  {"path": "report.pdf", "action": "archive", "target_relpath": "archive/report.pdf"}
]
```

将文件路径传给保存命令，再预览、执行：

```bash
dirtidy save-decisions /path/to/root <run_id> decisions.json
dirtidy apply-decisions /path/to/root <run_id> --dry-run
dirtidy apply-decisions /path/to/root <run_id>
```

还原本轮全部隔离项：

```bash
dirtidy quarantine-restore /path/to/root <run_id> --all
```

不可恢复的操作单独列在这里：下面命令会彻底删除**指定 run** 的隔离副本，确认不再需要后才使用。

```bash
dirtidy purge-quarantine /path/to/root <run_id> --yes
```

### 2.2 让模型辅助判断候选

模型分析可选，输出只是建议。网页「设置」页开启模型分析，填入 provider、地址、模型与密钥环境变量名，再到「审阅」页运行分析。

**什么时候用**：规则这一轮处理完之后。默认只分析**遗留项**——本轮候选里你还没表态、文件也还在的路径。已表态（保留或已设隔离/归档）、已隔离、已直接删除的项都不再发送。点击后会先显示范围（候选多少、已表态/已搬走多少、本次送多少、是否超过单次上限），确认后才调用模型。

命令行 `analyze` 仍是旧的全量口径（候选 + 浅层文件，受 `max_targets` 封顶）；要逐项对齐网页范围，按上面「遗留项」的定义用过审阅页的决策或直接调用网页接口。

密钥建议放在环境变量中。若直接在网页密钥框填入密钥，它会以明文保存到状态目录的 `models.yaml`；密钥框留空表示保持已有值。

命令行使用时，从仓库示例复制配置并填写：

```bash
cp src/dirtidy/configs/models.example.yaml models.yaml
dirtidy analyze /path/to/root <run_id> --config models.yaml
```

真实调用需要有效的模型配置和相应密钥。默认不发送文件正文，但摘要中的路径等信息仍可能外发；处理敏感内容前检查配置。正文发送由 `allow_external_content` 或 `allow_ollama_full_content` 显式开启。

没有模型时，可以只验证分析流程：

```bash
dirtidy analyze /path/to/root <run_id> --mock
```

`--mock` 不读模型配置、不联网，返回固定的待人工判断建议，**不能用来评价模型效果或决定删除**。

### 2.3 定时查看新增命中

```bash
dirtidy watch /path/to/root --interval 30
```

每隔 30 分钟扫描并报告变化，**不执行隔离**。默认跳过内容 hash，每轮最多运行 1800 秒；超时跳过本轮，下一轮继续。按 `Ctrl-C` 停止，也可在网页「监视」页启停。

### 2.4 清理 Cursor 的旧会话

这是独立的数据库清理命令，**不走目录隔离区**，也不需要先运行 `scan`。它删除选中的历史会话，删除后相应历史会丢失。首次验证建议通过 `--db` 指向独立的测试库副本。

先完全退出 Cursor，再预览超过 90 天的会话候选：

```bash
dirtidy cursor-cleanup --days 90 --measure
```

检查输出的数据库路径、候选数量与时间窗口。`--measure` 估算的是候选行字节数，不等于最终释放空间。

决定删除这些历史后才执行：

```bash
dirtidy cursor-cleanup --days 90 --apply
```

需要记住的边界：

- `--days 90` 仅选择有时间证据且明确超过 90 天的会话。header 旧但正文近期的保留；孤儿会话的时间未知或近期的保留。
- 共享 blob 全部保留。`--delete-blobs` 只用于兼容的只读候选统计，执行模式一律拒绝，确认口令不能放行。
- 不清理用户设置表 `ItemTable`，不碰 `agent-transcripts`、`chats`、Chromium `blob_storage` 或 IndexedDB。
- Cursor 正在运行，或无法判断其是否运行时，拒绝执行。

执行前会冷备份，默认位于库旁的 `CursorStateBackup-<时间戳>/`。默认压缩数据库并校验，成功后按 `--keep-backups` 保留最近的冷备份（默认 1 份），旧备份可能被回收。请预留备份和压缩所需空间，当前没有磁盘空间预检。

完成后重新打开 Cursor，手动核对近期会话能否打开、设置是否正常。这项检查不能由数据库结构校验代替；自动化测试也不等于在你当前 Cursor 版本上完成了真实恢复验证。

`--schedule-hours H` 是可选的定时轮询模式：不需要另加 `--apply`，检测到 Cursor 未运行时会实际清理。首次验证不要开启它。

## 3. 按需查阅

### 3.1 常见问题

| 遇到的情况 | 怎么处理 |
|---|---|
| `dirtidy: command not found` | 激活虚拟环境，或用 `.venv/bin/dirtidy` |
| 网页没有打开 | 查看终端给出的地址；确认服务仍运行。`serve` 只起服务，不自动打开浏览器 |
| 界面仍是上一次的结果 | 确认所选 run；在扫描页新建扫描，或用 `start --rescan` |
| 扫描超时 | 本轮结果不完整且未执行隔离；调大 `--timeout` 或设为 0 后重扫 |
| 想动的目录被保护拦下 | 点「为什么？」或用 `explain` 检查原因；内置保护不能关闭，`--protect` 只能增加保护 |
| 还原后没有覆盖原文件 | 原位置已有同名文件时会跳过；先检查原文件与隔离副本，不要直接覆盖 |
| 隔离后可用空间没增加 | 隔离副本仍占空间，确认不需要后彻底删除才释放 |
| 模型调用失败 | 核对配置、密钥环境变量与网络；`--mock` 只能检查管道是否可运行 |
| Cursor 清理被拒绝 | 完全退出 Cursor；不要绕过进程检查，也不要尝试用旧口令授权 blob 删除 |

同一目标目录不要同时运行多个 dirtidy 进程。当前没有根目录级单实例锁；强制杀进程或内存耗尽时，最后搬移的记录可能来不及写入清单。其他限制见 [已知缺口](06-已知缺口与后续.md)。

### 3.2 命令一览

表中列出完整选项，按需使用，不必逐条执行。方括号表示可省略的位置参数；默认 root 是当前目录。

| 命令 | 用途 | 选项与默认值 |
|---|---|---|
| `start [root]` | 必要时扫描，再起服务并打开网页 | `--rules`（default）`--quick` `--workers`（4）`--rescan` `--timeout`（0 秒，不限）`--protect` `--host`（127.0.0.1）`--port`（8765）`--no-browser` `--no-tray` |
| `scan <root>` | 扫描并保存 run；默认不搬文件 | `--rules`（default）`--quick` `--apply`（扫描后立即执行，跳过审阅）`--workers`（4）`--timeout`（0 秒）`--protect` `--dry-run` |
| `explain <root> <path>` | 解释相对路径的判定 | `--rules`（default）`--protect` `--json` |
| `apply-rules <root> <run_id>` | 执行规则隔离 | `--dry-run`（只预览）`--keep`（可重复） |
| `analyze <root> <run_id>` | 生成模型建议 | `--config` `--mock` |
| `save-decisions <root> <run_id> <file>` | 保存 JSON 决策数组 | 无 |
| `apply-decisions <root> <run_id>` | 执行已保存的候选决策 | `--dry-run` |
| `quarantine-restore <root> <run_id>` | 还原隔离项 | `--all` `--id`（可重复） |
| `purge-quarantine <root> <run_id>` | 彻底删除该轮隔离副本 | `--yes`（必需） |
| `serve` | 起本地服务，不自动开网页 | `--root`（.）`--run-id` `--host`（127.0.0.1）`--port`（8765）`--reload`（仅开发用） |
| `desktop [root]` | 起服务并开网页，不主动扫描 | `--host`（127.0.0.1）`--port`（8765）`--no-browser` `--no-tray` |
| `watch [root]` | 定时扫描，不搬文件 | `--rules`（default）`--interval`（30 分钟）`--full` `--rounds`（无限）`--timeout`（1800 秒）`--no-notify` `--protect` |
| `cursor-cleanup` | 清理 Cursor 旧会话，默认只统计 | `--days`（90）`--apply` `--db` `--backup-dir` `--no-orphan` `--no-vacuum` `--measure` `--keep-backups`（1）`--schedule-hours`（默认关闭）`--delete-blobs`（仅只读统计，执行拒绝）`--blob-confirm`（兼容，不授权删除）`--blob-pause`（兼容，3 秒） |

`scan --dry-run` 不搬文件，但当前实现仍创建扫描记录；不要将它理解为整个磁盘零写入。`--quick` 跳过内容 hash 和归档对照，因而不会提供完整的重复文件与解压残留识别。

### 3.3 记录和配置放在哪里

默认状态目录是 `<root>/.dirtidy/`：

| 位置 | 用途 |
|---|---|
| `runs/<run_id>/audit.md` | 阅读本轮审计报告 |
| `runs/<run_id>/meta.json` | 根目录、时间、规则与运行状态 |
| `runs/<run_id>/candidates.json` | 待人工判断的候选 |
| `runs/<run_id>/pending_auto_hits.json` | 待执行的规则命中 |
| `runs/<run_id>/quarantine_manifest.json` | 隔离与还原清单 |
| `runs/<run_id>/protection.json` | 保护拦截和人工保留记录 |
| `runs/<run_id>/errors.json` | 扫描中的权限、归档等错误 |
| `runs/<run_id>/decisions.json` | 已保存的人工决策 |
| `runs/<run_id>/ai_suggestions.json` | 模型建议（运行分析后） |
| `runs/<run_id>/purged_directly.json` | 已直删项目的留痕 |
| `quarantine/<run_id>/` | 仍可还原的隔离副本 |
| `settings.json` / `models.yaml` | 跨 run 的直删开关、模型开关与接入配置 |
| `hash_cache.sqlite` | 内容 hash 缓存 |

只读介质或不希望在目标目录写状态时，用 `DIRTIDY_STATE_DIR` 指向外部可写目录；之后所有命令及服务要沿用相同设置。

模型配置可由 `--config` 显式指定；CLI 未指定时按 `DIRTIDY_CONFIG`、当前目录 `models.yaml`、`~/.config/dirtidy/models.yaml` 查找。网页保存的配置位于状态目录，要在 CLI 明确使用它，可传 `--config /path/to/root/.dirtidy/models.yaml`。

本地网页没有鉴权，默认监听 `127.0.0.1`，不要暴露到公网。
