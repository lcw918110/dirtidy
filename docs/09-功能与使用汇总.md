# dirtidy — 功能与使用汇总

> 本文是**总览**：把功能、用法、注意事项收在一处，便于快速上手与交接。
> 逐项细节与设计取舍见 `docs/01` ～ `docs/08`，本文不重复论证。

## 1. 它是什么

跨平台（macOS / Linux / Windows）的**本地目录整理工具**。三步走：

```
规则隔离（默认进隔离区） → 模型分析残留 → 人工在 Web / CLI 终审「留 / 隔离 / 归类」
```

**核心设计取向：自动只到「候选 / 隔离区」为止，执行必须人工。** 这条贯穿全文——
后面所有的保护加固、`watch` 只扫不动、`archive` 不拦，都是它的推论。

**定位是单机、单用户的后台程序**：可无人值守长期跑（`watch` 定时扫描、`desktop` 常驻起服务），
也可被中断后重跑。稳定性与性能按后台程序的标准要求，见 `docs/08-稳定性与性能设计.md`。

## 2. 已实现的功能

### 2.1 扫描

- 递归枚举文件与目录，记录：**相对路径、大小、mtime、是否目录**。
- 内容 hash **按需计算**：只对「size 出现 ≥2 次」与「size 命中某个归档成员」的文件算 sha256。
  依据是「同内容必然同字节数」，所以漏算的文件既不可能重复、也不可能与归档成员相同——
  **结论与全量算等价，代价却小一个量级**。
- 扩展名不单独存字段（可由路径现算），500 万条下省约 250 MB。
- 权限不足记入 `errors.json`，**不中止整次运行**。
- hash 结果缓存在 `<root>/.dirtidy/hash_cache.sqlite`，**可中断续跑**（按 path+size+mtime 复用）。
- 单次运行有可选时限（`--timeout`，秒；`0` = 不限）。到点即停，但**已扫到的部分照常落盘**、
  退出码 `3`，且**本轮不执行隔离**——基于「只扫了一半的树」搬文件比不搬更糟。
  为什么用协作式检查点而不是 `signal` / 异步异常强杀，见 `docs/08` §1.5。

### 2.2 规则引擎

从 YAML 规则包加载，内置两个：`default`（24 条）、`server_workspace`（3 条）。

三种 action：

| action | 含义 |
|--------|------|
| `protect` | **最高优先级**。命中即永不自动隔离，也不进候选 |
| `auto_quarantine` | 高置信，`apply-rules` 时自动隔离 |
| `candidate_only` | 只进候选，等人工决定 |

`default` 包覆盖：VCS / 凭据 / 系统保留 / 密钥 / 项目标记 / CI 配置（保护类 6 条）；
Node、Python 缓存与 venv、JVM / Web / 工具链缓存、OS 元数据、编辑器交换文件、
字节码、临时分片、日志、空目录（自动隔离类 12 条）；
空文件、构建产物、安装包、归档、备份、数据库文件（候选类 6 条）。

**可选的 `purge_safe: true` 标记**（默认无一条生效）：把「重建成本为零」的规则标出来，
界面会在这些规则旁提示「建议直删」。默认行为**一点不变**（一律只进隔离区），
要不要开、开哪几条由你在界面上决定。当前标了 4 条：`dep_python_cache`、`dep_os_metadata`、
`dep_editor_swap`、`dep_python_bytecode`。

**「直删」是隔离路径上多加的一步，不是另一条路径**：

```
规则命中 → 过 keep 与保护复核 → 搬入隔离区 → 写清单 → 立刻物理删除该条 → 记入 purged_directly.json
```

所以保护判定与清单写入一个环节都不少：子树里躺着受保护路径的目录照样被整条拦下，
勾了「保留」的项照样不动。删除明细单独留痕（那些文件已不在磁盘上，隔离清单里也没有它们）。

**`when` 条件**可把「目录名」这类粗糙匹配收窄：

```
min_age_days / min_size_bytes / max_size_bytes / under / not_under / min_depth / max_depth
require: [source_free]
```

例：「`logs` 目录**且** 3 天没动过**且**里面没有源码」才自动隔离。

`--protect <相对路径>` 可额外护住某个路径（含其整棵子树），可重复。

### 2.3 保护（不可绕过）

两层，规则包只能加不能减：

1. **内置清单**（`src/dirtidy/rules/protect.py`，**规则包关不掉**）

   | 类别 | 内容 |
   |------|------|
   | 版本控制元数据 | `.git` `.hg` `.svn` `.bzr` |
   | 工具自身状态 | `.dirtidy` |
   | 凭据 / 云配置目录 | `.ssh` `.gnupg` `.aws` `.gcloud` `.azure` `.kube` `.docker` `.cargo` |
   | 系统保留目录 | `lost+found` `$RECYCLE.BIN` `System Volume Information` `.Trash` `.Spotlight-V100` `.fseventsd` … |
   | 密钥 / 凭据文件 | `.env` `.env.*` `*.pem` `*.key` `*.p12` `*.pfx` `*.jks` `*.keystore` `*.kdbx` `*.ppk` … |

2. **规则包里的 `protect` 规则**（`default.yaml` 中 6 条）

判定是**双向**的：

- 目录命中保护 ⇒ 其**整棵子树**受保护（`.git` 被保护 ⇒ `.git/objects/…` 不可被搬走）
- 一个命中自动隔离的**目录**，若子树内含受保护路径 ⇒ **整条命中被拦下**，记入 `protection.json`

第二条不可省：否则保护会被「搬走它的父目录」绕开——
`node_modules` 命中 dep 规则时，`node_modules/.env`、`node_modules/id_rsa` 会被一并端走。

覆盖**所有会搬文件的执行路径**（`apply-rules` / `apply-decisions` / `scan --apply`），
共用同一份实现；判定器参数是**必填**的，调用方漏传会直接报错，而不是让保护静默失效。

### 2.4 重复文件与归档残留

- **重复组**：按内容 hash 分组，**默认仅候选**，不自动隔离。
- **归档残留**：对 zip / tar / tar.gz 枚举成员并算成员内容 hash，与磁盘文件 hash 对照，
  达阈值（≥ 0.8）才标 `archive_extracted`。**禁止仅凭压缩包文件名或同名目录判定。**
- 旁路压缩包像安装分发的，基于成员结构探测后标候选，默认不自动隔离。
- 0 字节文件**不参与重复组判定**（否则 `.env` / `id_rsa` 这类空文件会被凑成「内容相同」诱导误操作）。

候选（`candidates.json`）的 5 种 kind：

| kind | 含义 |
|------|------|
| `rule` | 规则命中（`candidate_only` 类） |
| `duplicate_group` | 重复文件组 |
| `archive_extracted` | 归档已解压残留（hash 对照达阈值） |
| `archive_content` | 归档内容相关，仅候选 |
| `archive_review` | 归档超解析预算 / 不可读，交人工 |

### 2.5 隔离区与还原

隔离区是**中间状态**：文件已离开原位，但还在磁盘上、占着空间。所以它有两个出口——
确认不需要了**彻底删除**释放空间，发现删错了**还原**回原位。

- 默认把目标**移入** `<root>/.dirtidy/quarantine/<run_id>/`，**不直接抹盘**。
- 记录原路径、隔离路径、规则 id、时间、大小、hash（若有）。
- 还原：`quarantine-restore --all | --id <id>`；原路径已有文件时**跳过不覆盖**。
- 彻底删除：`purge-quarantine --yes`（整区）或界面上按条删除。
- 界面上显示**每条与合计的占用空间**（实算磁盘占用；清单里的 `size` 对目录恒为 0，
  直接汇总会显示成「0 B」）。
- 按条彻底删除会**同步收敛清单**——清单与磁盘始终一致，界面上的「已隔离」列表因此可信，
  不必猜某一条还在不在。整区清除等价于「删光全部条目 + 清掉空的隔离目录」。
- 越出状态目录的路径（历史脏数据 / 被手改过的清单）**拒绝删除但保留在清单里**，
  让问题可见，而不是静默删掉或静默忽略。

**人工保留（`--keep` / 界面勾选）的判定是双向的**，缺任何一向都会被绕过：

- **向下**：保留一个目录 ⇒ 它子树内的命中也保留。否则子项被搬走 → 目录变空 →
  空目录清扫再把空壳收走，用户勾的「保留」等于没生效。
- **向上**：保留项落在某个命中目录内部 ⇒ 那个目录本轮也不能动——搬走父目录等于把它一起搬走。

### 2.6 审计产物

每次 run 在 `<root>/.dirtidy/runs/<run_id>/` 下产出：

| 文件 | 内容 |
|------|------|
| `meta.json` | run 元信息（根目录、时间、规则包、计数） |
| `inventory.json` | 扫描清单（流式写盘） |
| `candidates.json` | 全部候选 |
| `quarantine_manifest.json` | 隔离清单（可据此还原） |
| `protection.json` | 受保护 / 被拦下 / 用户保留的记录 |
| `protect_policy.json` | 本次生效的保护策略快照 |
| `pending_auto_hits.json` | 待自动隔离项 |
| `purged_directly.json` | 命中直删规则、搬入隔离区后立即物理删除的条目（这些文件已不在磁盘上） |
| `errors.json` | 坏输入（权限、坏归档等） |
| `decisions.json` | 人工决策 |
| `ai_suggestions.json` | 模型建议 |
| `ai_meta.json` | 模型调用元信息（含外发计数） |
| `audit.md` | 人类可读审计报告 |

状态目录下还有两份**跨 run 的设置**（CLI 与 Web 读同一份）：

| 文件 | 内容 |
|------|------|
| `settings.json` | `auto_purge_rules`（开了直删的规则 id，默认空）、`use_model`（是否启用模型分析，默认 false） |
| `models.yaml` | 模型接入配置（界面可填；格式与项目原有 `models.yaml` 一致） |

### 2.7 模型分析（`analyze`）

- Provider：`openai_compatible`、`ollama`。
- 输入**默认安全摘要**：路径（可脱敏）、扩展名、size、mtime、类型、文本抽样上限、hash 前缀；
  **密钥类 / 二进制不抽样**。
- **外发正文默认关**，两条显式开启路径：
  - `provider: ollama` 且 `allow_ollama_full_content: true`（本机）
  - `provider: openai_compatible` 且 `allow_external_content: true`（外发，需显式承担）
- `summary.max_targets` 给单次外发封顶（默认 500）。
- **仅建议，不自动执行**。`--mock` 可在无密钥时跑通全流程。

> **`--mock` 是桩（stub），不是「简化版模型」。** 它**不读配置、不联网**——
> `analyze_run(mock=True)` 时连 `models.yaml` 都不加载，直接构造 `{"provider": "mock"}`。
> 它按扩展名把文件粗分成 doc / source / other，然后对每条返回**固定占位值**
> （`value: needs_human`、`confidence: 0.4`、`action: review`、`rationale: mock provider`）。
>
> **所以 mock 的输出不能用来做决策**——它等于说「全都交人工」。它的用途是：
> 无密钥 / 无网络时跑通全流程、让 CI 与单测不依赖真实 API、演示 Web 界面的 AI 建议区块，
> 以及排查「问题出在管道还是出在模型」（mock 通、真模型不通 ⇒ 查配置与网络；反过来 ⇒ 查管道）。

**接入真实模型的 4 步**：

```bash
# 1. 从包内示例复制（models.yaml 不随包分发）
cp src/dirtidy/configs/models.example.yaml models.yaml

# 2. 编辑 models.yaml：选 provider、填 base_url / model
#    provider: ollama              本机跑，数据不出机器，不需要密钥
#    provider: openai_compatible   任意 OpenAI Chat Completions 兼容端点

# 3. 密钥放进环境变量——yaml 里写的是「变量名」，不是密钥本身
export DIRTIDY_API_KEY=sk-xxxx

# 4. 跑
dirtidy analyze /path/to/root <run_id> --config models.yaml
```

配置查找顺序：`$DIRTIDY_CONFIG` → `./models.yaml` → `~/.config/dirtidy/models.yaml`。
**找不到就报错，不会静默回退到 `models.example.yaml`**——避免把示例当正式配置用。
`models.yaml` 已在 `.gitignore` 中，密钥只走环境变量，两者都不入库。

**也可以全部在界面上配**（等价，不必碰命令行）：

1. 打开「设置」页 → 勾选**启用模型分析**（默认关闭，不打开就完全不外发）。
2. 选 provider，填 `base_url` / `model` / 密钥环境变量名。
3. 密钥可以填环境变量名（推荐，密钥不落盘），也可以直接在界面上填——后者会以**明文**
   写进 `<root>/.dirtidy/models.yaml`，界面上会提示这一点。密钥框留空表示**保持原样**，
   不是清空（表单不回显密钥，若当成清空会让已保存的密钥悄悄消失）。
4. 回到「审阅」页点**运行模型分析**。

配置存在状态目录里，所以**界面与命令行用的是同一份**，不会出现两边不一致。
界面上不暴露 `mock`——它是给脚本化演示与排查用的桩，不是给终端用户选的 provider。

### 2.8 决策与执行

- 决策三态：`keep` / `quarantine` / `archive`（archive 需目标相对路径，缺省落到 `archive/<文件名>`）。
- Web 或 `save-decisions` 写入 `decisions.json`，`apply-decisions` 执行。
- **隔离前同样复核保护**，被拦下的记入 `skipped` 与 `protection.json`。
  **`archive` 不拦**——它是显式指定目标的归类，文件仍在根内可找回，与「清理」语义不冲突。
- 规则自动隔离可在执行前人工保留（CLI `--keep` / Web 勾选），保留项本轮不动并登记
  `protection.json`（`protect_rule_id=user_kept`），可审计追溯。
- 隔离计划（`plan_quarantine`）是**预览与实跑的唯一来源**：`--dry-run` 报出的
  「会搬哪些、拦下哪些」与真实执行逐条一致。

### 2.9 本地 Web 控制台（`serve` / `desktop`）

界面按八个功能分页，**覆盖主流程 CLI 能力**（`start` / `serve` / `desktop` 本身就是「起界面」；
`cursor-cleanup` 是独立 CLI 支线，不设界面入口）：

| 分页 | 做什么 |
|------|--------|
| **概览** | **引导区**（一句话说明「现在该做什么」+ 一个按钮）、四步步骤条、统计卡、run 选择（显示「10-17 13:13 · 命中 4 · 候选 4」，不再是一串机器时间；完整 run id 摆在旁边供命令行复制）、完整流程说明（折叠） |
| **扫描** | 规则包、并行线程数、跳过 hash、额外保护路径、是否立即执行；一键建 run。**扫描期间显示进度**（已用秒数 + `内容 hash 123/456`），避免大目录下界面像卡死；**扫完停在扫描页**：先给一句结论（多少项可清理、多少项需要你判断、合计约多少空间），再**按占用降序**分规则列出「这是什么 + 建议 + 占用」，每组可展开看具体文件，最后给「去审阅页逐条确认」入口。注意「扫描后立即执行」是**跳过审阅的捷径**，想按流程走就别勾它 |
| **审阅** | 顶部**四色图例**（建议清理 / 可以清理 / 需要你判断 / 受保护）；**① 待自动隔离**（**这是什么 / 建议 + 删了怎么办 / 占用 / 动了会怎样**，可勾选保留、可批量全选），上方可按**建议档位**与**路径关键字**筛选、可勾「**按建议分组**」（三档各一段，每段标条数与合计占用），**表头点「路径 / 建议 / 占用」可排序**（同列再点切方向，箭头指示），批量按钮在表格上方（先选再看），底部显示「本轮将搬走 X 项」+「下一步：去执行」；**② 候选 / 建议**——「建议」分「规则判断」与「模型参考」两层，都**不自动生效**，每行默认「保留不动」，要采纳点「采纳全部建议」（只填尚未表态的行），候选表支持**批量选择**（全选 + 批量设为保留/隔离/归档），底部同样显示「下一步：去执行」；重复组（报账 + 单选保留 + 其余标记隔离）、受保护清单、运行模型分析 |
| **执行** | **单独成页**：汇总将要搬走的内容——规则命中清单（显示保留标记）+ 候选决策清单（隔离 / 归档）。每条执行路径各带预览与确认按钮。规则统计来自后端 dry-run（实际搬走 / 直删 / 保留 / 保护拦下），未核对时禁用执行；候选预览使用当前未保存决策，不保存文件。确认后按动作隔离（可还原）、归档，或按已开启的直删设置删除（不可还原） |
| **隔离区** | 每条占用与合计占用、按条 / 全部**还原**与**彻底删除**、直删留痕 |
| **规则** | 规则包明细（**中文短名 + 动作人话** / 匹配 / 原因，id 缩成小字）、逐条开关「直删」、生效保护清单（标出哪些来自内置） |
| **设置** | 是否启用模型分析、provider / base_url / model / 密钥、外发规模上限 |
| **监视** | 启停后台监视，显示轮次、当前命中、每轮新增与消失 |

待自动隔离摆在候选之前——它是「不误删」的终审入口，看不到规则打算动什么，终审就无从谈起。
列表里被上层目录命中的条目会标成「已含在上层目录里」（执行时只搬父目录），
免得页面写着「N 项」而实际搬走更少。规则编号不再占一整列，缩成中文说明下的小字。

- 每次载入 run 都清空旧决策再读已保存值；切换 run 时还会清空保留与两类勾选，避免上一轮选择污染另一轮。
- 受保护清单与生效策略显示保护原因，规则 id 放在悬停提示，不再用内部编号替代解释。
- 建议档位的顺序、标签与说明从 `/api/meta` 读取，唯一来源是 `advice` 模块，前端不再硬编码副本。
- 列表里的「建议」由后端 `dirtidy/advice.py` **统一算好**（建议清理 / 可以清理 / 需要你判断 / 受保护），
  前端只负责显示。规则包加了 `purge_safe` 或改了动作，界面会跟着变，不会出现
  「界面说可以清理、实际直接删除」。这条有静态守护用例：前端渲染函数里不许出现判定依据。
- 每条还会给两样**能让人下决心**的东西：**占用大小**（按大小降序，先看大的）与
  **「删了怎么办」**（`recover`，如 `npm install`、`无需恢复`、`无法恢复`）。
  只说「可以清理」等于让用户凭信任点按钮——这是 Windows 磁盘清理与 BleachBit 的共同做法。
- 规则一律显示**中文短名**（规则包的 `label`，如「Node 依赖」「旧日志」），
  `dep_node_modules` 这种内部编号退成小字/悬停提示。规则页的「动作」也翻成人话
  （自动隔离 / 保护 / 只进候选），不再铺 `auto_quarantine`。
- **run 下拉说人话**：`10-17 13:13 · 命中 4 · 候选 4`，不再是 `2026-10-17T042716+0000-c9874f`；
  完整 id 摆在旁边，命令行 `dirtidy apply-rules <root> <run_id>` 直接复制。
- **表头可点排序**（路径 / 建议 / 占用），同列再点切方向，箭头指示当前方向；
  同值按路径兜底，顺序不会在每次重渲染时乱跳。
- **按建议分组**：勾上后三档各一段，每段标「N 项 · 合计 X」，节内仍按当前排序。
  分节横条而不是并排三栏——三栏会把每栏压到 500px 左右，路径都显示不全。
- **筛选只影响显示**：按建议档位或路径筛完之后，执行范围仍是全部命中（勾了「保留」的除外），
  按钮与确认框按后端对全量命中的执行计划报数（已经去重、复核保护与保留），而不是按筛选结果或命中原始条数报数。

**视觉与交互的一致性**（2026-10-21 改造）：

- **样式表 token 化**：所有颜色/间距/字号/圆角都走 CSS 变量，`:root` 之外不许写裸色值。
  改造前 447 行里有 36 处硬编码色值（29 个不同值）、只有 7 个变量——同一语义在五处各写一遍，改一处就会漂。
  颜色只用于编码**后果**（可还原 / 不可还原 / 待判断 / 受保护），没有装饰性用色。
- **每页首屏结构一致**：`h2` + 一句引导语，右侧放「看哪个 run」这类上下文；
  长说明收进可展开的「跑完之后会看到什么」「三种去向的区别」等折叠块——
  信息一条没删，只是不抢首屏注意力。
- **会动文件的按钮都有忙态**：禁用 + 转圈 + 文案换成「执行中…」，重复点击直接忽略。
  「清空隔离区」点两次是会删空的，这个按钮尤其需要。
- **表头与焦点可达**：所有可交互元素有清晰焦点环；窄屏（≤720px）表格横向滚动而非挤成竖排单字；
  系统开「减少动态效果」时入场动画与转圈一起停。
- **扫描进度**：扫描期间前端轮询 `/api/scan/progress`，状态条显示已用秒数与 hash 进度；
  同一时刻只允许一次扫描（第二次直接 409），免得产生两个 run、两份隔离清单。
- 每条路径旁有「**为什么？**」按钮，弹窗先展示**四段人话结论**（这是什么 / 系统会怎么办 /
  为什么 / 删了怎么恢复，由后端 `human_summary()` 统一算好），底下把逐条规则判定收进折叠的
  「技术判定明细」。技术明细与 CLI `explain` **逐字一致**，不会出现「网页说的和 CLI 说的不一样」。
  弹窗里可**一键复制**（人话 + 技术明细的合体，剪贴板 API 不可用时退回 `execCommand`，局域网 IP 打开网页也能复制）。
- 支持深链 `/?explain=<相对路径>` 直接打开该弹窗，便于把结论发给别人。
- 操作结果走**底部状态条**：字段名翻成人话（如「隔离 3　直删 1」），错误常驻并标红、普通提示 6 秒后自动收起。不再把接口返回体原样铺在页面上。
- **状态转移后出汇总摘要**：执行隔离 / 候选决策 / 还原 / 彻底删除等动作完成后，状态条给一整句
  「✓ 搬进隔离区 3 项。当前待处理 0 项，隔离区累计 3 项（1.2 MB）」——先报「搬走了多少」，
  重载后再补「还剩多少」，而不是零碎的 `quarantined: 3`。数字全部来自后端返回体，前端不自己算判定。
- **切 tab 丝滑**：激活页有轻量淡入动画（0.16s），并尊重系统「减少动态效果」设置；切页回到内容顶部，
  避免从上一页的滚动位置半路切入。固定顶栏 + 内容区内部滚动，切页高度不再跳动。
- 页面不加载任何外部资源，由严格 CSP 兜底；前端不使用 `innerHTML`（有静态守护用例）。

### 2.10 桌面壳（`desktop`）

- 流程：启动本地服务 → 等就绪 → 自动打开浏览器 → 阻塞直到退出。
- 首选端口被占用**自动顺延**，不让用户自己排查端口冲突。
- 就绪判定走 `GET /api/health` 而**非 TCP 连通**：TCP 通了不代表路由已挂好，
  此时打开浏览器会看到连接被拒。
- 托盘图标是**可选增强**：未装 `pystray` 时降级为「按 Ctrl-C 退出」，
  需要时装 `pip install dirtidy[desktop]`。
- **只是启动器，不改变任何行为。**

### 2.11 定时监视（`watch`）

- 定期扫描并报告**新增**的命中项。
- **硬边界：只扫描，绝不执行隔离。** 源码里不存在任何执行入口，并有静态守护用例守着这条不变量。
  监视天然是「自动触发」，而本工具的核心价值是「自动只到候选 / 隔离区为止」——
  自动搬文件等于把保护判定加固全部作废。
- 通知失败（系统不支持、无通知服务）静默降级为控制台输出。
- 单轮有时限（`--timeout`，默认 **1800 秒**）。CLI、Web 与 `run_watch` 共用 `WATCH_DEFAULT_TIMEOUT`，界面可设置每轮时限（0 不限；接口拒绝负数）。超时只跳过这一轮、下一轮照常，**且不更新比对基线**
  ——拿只扫了一半的集合去比，会把没扫到的全报成「消失」，那是在编数据。无人值守的场景必须
  有默认值（否则「一轮卡住 = 监视停摆」），而 `scan` / `start` 有人盯着，默认不限（0）。见 `docs/08` §1.5。
- 界面「监视」页可启停后台监视并显示进度（轮次、当前命中、每轮新增与消失）。
  停止会**立刻唤醒**，不必等满一个间隔（默认 30 分钟，傻等会让人以为按钮坏了）。

### 2.12 Cursor 状态库清理（`cursor-cleanup`）

清理本机 Cursor 的全局状态库 `state.vscdb`（实测约 **75 GB** / 838 万行）。这是**独立于目录整理**的一条支线：
它不碰你的目标目录，只处理 Cursor 自己的状态文件。

**为什么值得做**：`state.vscdb` 里 99% 以上的体积是 `agentKv:blob`（agent 运行时大对象：
图片 / 附件 / 上下文快照）。绝大多数是历史垃圾——真机实测 **681,182 个 blob 里只有 13,867 个还被人引用，
667,315 个（97.9%）无人引用**。

**默认只统计、不改库**。跟 dirtidy 其他破坏性命令一致：不加 `--apply` 一个字节都不动。

```bash
dirtidy cursor-cleanup                      # 干跑：只报「有多少可清」
dirtidy cursor-cleanup --apply              # 真正清理
dirtidy cursor-cleanup --apply --days 30    # 只保留最近 30 天的会话
dirtidy cursor-cleanup --measure            # 干跑时额外算能腾出多少空间
```

**安全设计**（这几条是底线，不是可选项）：

| 设计 | 为什么 |
|---|---|
| 默认干跑 | 破坏性命令默认不动手 |
| **绝不删 `ItemTable`** | 那是用户设置（插件 / 主题 / 快捷键） |
| **只删无引用的孤儿 blob** | 被会话正文引用的 blob 一个不动 |
| **引用来源扫全部前缀** | 只扫会话那三个前缀会漏掉 `ofsContent:` 这类同样引用 blob 的键——漏扫即误删活数据 |
| Cursor 在跑就拒绝执行 | 改库会抢 WAL 锁，可能让 Cursor 报 `storage file corrupted` 而起不来 |
| **判断不了是否在跑，也按「在跑」处理** | 返回「没在跑」的语义是「可以放心改库」。取不到进程列表却放行，等于在 Cursor 正写库时拆它的库（原实现在 Windows 上正是如此） |
| 清理前冷备份 + 压缩后校验 | 拿损坏库覆盖好库是灾难；校验不过就中止替换 |
| **备份跟着被清理的库走** | 备份目录默认落在库旁边，而非写死用户 HOME 下的 Cursor 路径；否则用临时库调用（测试 / 小工具）会往真实应用目录里塞东西 |
| **边清理边记审计** | 删 blob 分批做、全程几十分钟，中途被杀时内存里的结果会蒸发；每阶段追加一行 JSONL，断了也留着已发生的记录 |

**判定只此一处**：`plan_blob_cleanup` 算出的名单，预览与实跑共用同一个——不会「预览说该留、执行却删了」。

**跨平台**：默认库路径按平台推（macOS `~/Library/…`、Linux `~/.config/Cursor`、Windows `%APPDATA%\Cursor`）。
写死 macOS 会让另外两个平台一上手就报「找不到数据库」，功能等于不存在。

**耗时预期**：引用扫描要顺序读一遍 767 万行会话正文。真机实测：参考实现只扫三个前缀就要
**1163 秒**，本模块扫全部前缀约 **33 分钟**。这是判断「谁还引用着 blob」的必要代价
（用 SQL 逐个哈希查等于全表扫，单个哈希实测 7 分钟无结果）。

**真机对照实验**（只读，未改动真机任何数据）：把参考实现的「三前缀扫描」与本模块的
「全前缀扫描」在同一份真库上各跑一遍，结果：

| 项 | 数值 |
|---|---|
| 参考实现扫到的 blob 引用 | 13,866 |
| 全前缀扫描覆盖的 blob 引用 | 13,867 |
| **差值 = 参考实现会误删的活 blob** | **1** |
| 无人引用的真孤儿 blob | 667,315 |

即：参考实现确实会误删 **1 个**仍在被 `ofsContent:` 类键引用的 blob。数量不大，
但性质是「删掉还在用的数据」，所以本模块坚持扫全部前缀。

## 3. 用法

### 3.1 安装

```bash
cd ~/Desktop/git/dirtidy
python3 -m venv .venv                 # 需要 Python >= 3.11
.venv/bin/python -m pip install -e ".[dev]"

source .venv/bin/activate             # ★ 不激活的话 dirtidy 不在 PATH 里
dirtidy --version                     # 能打印版本号才算装好

# 可选：桌面壳的托盘图标（不装也能用，只是没有托盘）
.venv/bin/python -m pip install -e ".[desktop]"
```

> 不想每次激活：把 `dirtidy` 换成 `.venv/bin/dirtidy`（等价于 `.venv/bin/python -m dirtidy`），
> 或者一次性软链到 PATH 里：
> `ln -sf "$PWD/.venv/bin/dirtidy" /usr/local/bin/dirtidy`（权限不足加 `sudo`）。

### 3.2 命令一览

### 3.3 典型工作流

**最短路径——一条命令：**

```bash
dirtidy start /path/to/root      # 没有结果就先扫描 → 起本地服务 → 打开浏览器
```

界面上照着概览页的提示走即可：它会直接告诉你「现在该做什么」，并给出一个按钮。
以下是拆开做（脚本化 / 精细控制）时的完整流程：

```bash
# ① 只扫描，先看有什么
dirtidy scan /path/to/root --rules server_workspace

# ② 对某个路径问「为什么会被 / 不会被动」
dirtidy explain /path/to/root src/logs --rules server_workspace

# ③ 预览隔离计划（会搬哪些、哪些被保护拦下）
dirtidy apply-rules /path/to/root <run_id> --dry-run

# ④ 执行；想留住某项就 --keep
dirtidy apply-rules /path/to/root <run_id> --keep logs/keep-me.log

# 或一步到位：扫描并隔离
dirtidy scan /path/to/root --rules default --apply

# ⑤ 模型分析（无密钥可 --mock）
dirtidy analyze /path/to/root <run_id> --mock

# ⑥ 人工终审
dirtidy serve --root /path/to/root --port 8765     # 浏览器审阅
# 或
dirtidy desktop /path/to/root                       # 起服务 + 自动开浏览器

# ⑦ 还原 / 清理
dirtidy quarantine-restore /path/to/root <run_id> --all
dirtidy purge-quarantine /path/to/root <run_id> --yes
```

### 3.4 目录与产物

```
<root>/.dirtidy/
├── runs/<run_id>/          # 每次 run 的全部产物（见 §2.6）
├── quarantine/<run_id>/    # 隔离区（文件搬到这里）
├── settings.json           # 跨 run 设置：直删规则、是否启用模型分析
├── models.yaml             # 模型接入配置（界面保存时写在这里）
└── hash_cache.sqlite       # 内容 hash 缓存（可中断续跑）
```

### 3.5 环境变量

| 变量 | 作用 |
|------|------|
| `DIRTIDY_CONFIG` | 指定 `models.yaml` 路径（优先于 `./models.yaml` 与 `~/.config/dirtidy/models.yaml`） |
| `DIRTIDY_STATE_DIR` | 把整个 `.dirtidy/` 重定位到外部可写目录——**只读介质或不想污染目标目录时用** |
| `<api_key_env>` | 模型密钥。**变量名由 `models.yaml` 的 `api_key_env` 指定**（默认 `DIRTIDY_API_KEY`）。界面里也可以直接填密钥，那种情况下写进状态目录的 `models.yaml`（明文）；环境变量的优先级低于显式填写的密钥 |

### 3.6 退出码

| 码 | 含义 |
|----|------|
| `0` | 成功 |
| `1` | `explain` 的目标路径在扫描结果里找不到（其余子命令不用 1） |
| `2` | 用法 / 参数错误，或**拒绝执行**：`--dry-run` 与 `--apply` 互斥、路径无法解释、`purge-quarantine` 缺 `--yes` |
| `3` | **单次运行超时**（`--timeout` 到点，仅 `scan` / `start`）：已扫到的部分结果照常落盘，但**本轮不执行隔离**。与「跑失败」区分开——失败是「什么都没得到」，超时是「得到了一部分」。`watch` 单轮超时不返回 3（它只跳过本轮，继续监视） |

## 4. 注意事项

### 4.1 安全（先看这节）

1. **默认隔离，不直接抹盘。** 只有 `purge-quarantine --yes` 或界面上明确点「彻底删除」才真正删除。
2. **执行前先 `--dry-run`。** `scan` / `apply-rules` / `apply-decisions` 都支持，
   先看「会动哪些、哪些被保护拦下」再决定。
3. **「直删」是隔离路径上多加的一步，不是绕过隔离。** 它仍然先过人工保留与保护复核、
   搬入隔离区、写清单，然后才物理删除，并另记 `purged_directly.json`。
   **默认一条都不开**，要开得自己在「规则」页逐条勾。开了之后那些条目**不可还原**。
4. **保护清单关不掉。** 内置清单（VCS、凭据目录、系统保留、密钥文件）不因规则包配置而失效；
   `--protect` 只能**增加**保护。
5. **保护是双向的。** 目录命中保护 ⇒ 子树受保护；命中隔离的目录若含受保护后代 ⇒ 整条拦下。
   所以「人工把整个目录标成 quarantine」也不能绕开保护。
6. **人工保留也是双向的**（见 §2.5）：保留目录 ⇒ 子树保留；保留项在某个命中目录里 ⇒ 该目录本轮不动。
7. **模型外发默认只传安全摘要**，正文外发需显式开启（`allow_external_content` / `allow_ollama_full_content`），
   且 `summary.max_targets` 给单次外发封顶。模型分析**默认关闭**，不打开就完全不外发。
8. **`watch` 不会动你的文件**，只扫描并报告。
9. **处理敏感目录时加 `--quick`**，完全跳过内容 hash 与缓存，不读文件内容。

### 4.2 使用

- **`models.yaml` 不随包分发**，要自己从 `src/dirtidy/configs/models.example.yaml` 复制，
  或直接在界面「设置」页填。
- **界面里填的密钥是明文落盘的**（写在 `<root>/.dirtidy/models.yaml`）。想避开就把密钥
  放进环境变量、界面只填变量名。`models.yaml` 这个文件名已在仓库 `.gitignore` 里，
  但目标根若另有版本控制，请自行确认已被忽略。
- 无模型时 **Step1（扫描 + 规则）完整可用**，`analyze` 只是可选增强。
- 规则包含「空目录自动隔离」时，搬走子项后新空出来的父目录会**再清几轮**。
- `explain` 与真实执行共用同一份判定，所以不会出现「解释说要动、实际不动」。
  反过来，看到「整条拦下」就是真的不会动，不用再试。
- 界面上「待自动隔离」列表里被上层目录命中的条目会标成「已含在上层目录里」——
  执行计划去重后只搬父目录；按钮数字来自后端计划，不应再以原始命中数多报。预览后文件可能变化，实跑仍会再次复核保护。

### 4.3 性能与规模

- 面向**百万文件 / T 级数据**设计：500 万条条目常驻内存约 **1.07 GB**（上限 2 GB）。
- 非 quick 扫描只对必要文件算 hash，结果缓存在 SQLite；重复扫描同一目录时快得多。
- `--workers N` 并行算 hash（默认 4）。
- 可复现基准与冒烟：

  ```bash
  python scripts/bench_scale.py --files 1200
  python scripts/smoke_e2e.py
  ```

### 4.4 已知边界

- **归档残留对照是「精确字节」**：换行符被转换过的文件**不会**被认作残留——
  这是对的（`a\n` 与 `a\r\n` 确实是不同文件），本工具从不「猜内容相近」。
- 隔离中途被 **SIGKILL / OOM 硬杀**时，最后几条已搬记录可能丢出清单
  （Python 异常与 Ctrl-C 已覆盖）→ T-1（**已决定接受**，不做硬杀还原保证）。
- **无 root 级单实例锁**：两个进程同时扫同一 root 会互相踩状态目录 → 待办 T-2。
- ~~无整体运行超时~~：**已落地**（`--timeout` + 协作式检查点）→ **T-3 已完成**，见 `docs/08` §1.5。
- **无写盘前磁盘空间预检** → 待办 T-4。
- 完整台账（含触发条件与验收标准）见 `docs/06-已知缺口与后续.md` 的「待办台账」。

## 5. 明确不做 / 非目标

- **没有「默认就彻底删除」的规则**——所有 `auto_quarantine` 默认只到隔离区为止。
  直删是一个**逐条显式开启**的选项（见 §2.2），且仍走隔离路径、仍留审计；
  它省的是空间，不是把「可逆」这件事取消掉。
- **企业账号 / 多租户**：已彻底移除，不再作为议题。
- **Electron / Tauri 打包签名**：桌面壳只做薄壳（远期项 T-9，当前形态约束不变）。
- 归档残留**不做模糊匹配**：只报字节级确证，宁可不报交人工，也不误报。
