# dirtidy — 已知缺口与后续

第一期功能缺口已补完；但 2026-10-09 的独立审核又发现了一批**安全与边界**类缺陷（见下方「2026-10-09 审核新增待办」），其中多数已修，少数仍开放。桌面壳、定时监视、企业账号仍是愿景里的**非目标**，不在待办里。

## 已完成

| 项 | 落实 |
|----|------|
| 扫描 / 规则隔离 / hash 候选 / 审计 | CLI + 夹具 |
| Web 审阅 | FastAPI 路由测例：保存决策并执行 |
| 彻底清除 | `purge-quarantine` 无 `--yes` 返回失败且不删；有 `--yes` 删除隔离副本 |
| 跨平台路径 | inventory 相对路径固定 posix，不含反斜杠 |
| 空目录多轮 | 隔离子项后再清因此变空的父目录（最多 8 轮） |
| 压缩包启发式 | 成员名区分安装包类与源码快照类，仍只进候选 |
| 大目录 hash | `--workers` 并行；`.dirtidy/hash_cache.sqlite` 按 size+mtime 复用，中断后下次接着算 |
| 模型联调 | OpenAI 兼容与 Ollama 用假 HTTP 走通请求与 JSON 解析；无密钥时用 `--mock` |
| 本地首提交 | 本仓 `git` 已有提交；远程地址等指定后再加，不默认推到公共远端 |
| 文档与实现对齐 + 健壮性修复 | 规则 ID 表与 YAML 对齐；加密/不可读归档术语统一为 archive_review；CLI 契约补 save-decisions 并订正 serve 参数；README 补 hash_cache.json 安全约定；删 scanner 死代码；iter_archive_members 补捕获 NotImplementedError；load_model_config 不再回退加载 models.example.yaml（本轮 18 测全绿） |
| 打包内置规则包 + README 版本提示 + 文档一致性测试 | configs/rules 迁入 src/dirtidy/rules/packs/ 并写入 package-data；README 显式 Python >=3.11；新增 tests/test_docs_consistency.py 守护文档与 YAML 一致性 |

## 2026-10-09 业务规则与规模（第二轮）

按「业务级规则既不能误删也不要留下无效的」「几百万文件 / T 级数据作为非功能要求」两项诉求落地。

### 规则层（防误删 + 不留无效）

| 项 | 状态 | 说明 |
|----|------|------|
| 无保护概念，目录名规则可误删 | 已修 | 新增 `protect` 动作，最高优先级且**与规则书写顺序无关**；命中路径（目录含整棵子树）既不隔离也不进候选，只登记到 `protection.json` |
| 保护清单可被规则包关掉 | 已修 | 内置清单写在 `rules/protect.py`（VCS 元数据、凭据目录、系统保留目录、密钥文件），规则包只能追加不能删除 |
| pending 列表被改后可绕过保护 | 已修 | `apply-rules` 在真正搬文件前用当前生效保护清单**再复核一遍** |
| 目录名规则太糙 | 已修 | 新增 `when` 条件：`min/max_age_days`、`min/max_size_bytes`、`under`/`not_under`、`min/max_depth`、`require` 守卫（`source_free`） |
| 规则笔误要扫完才发现 | 已修 | 规则包加载即校验 action / match.type / when 字段 / 必填项 / id 重复 |
| 覆盖不全，仍会留无效文件 | 已修 | `default` 规则包 9 → 24 条：多生态缓存、编辑器交换文件、未完成下载、安装包/压缩包/备份/本地库候选；`server_workspace` 的 `logs` 目录加「3 天未更新 + 无源码」双重条件 |

### 使用层缺陷修复（2026-10-10）

真机跑通全流程（scan → explain → apply-rules → analyze → serve）时发现的三处问题：

| 项 | 状态 | 说明 |
|----|------|------|
| explain 的逐条列表查不到「谁保护的」 | 已修 | 结论区说 `builtin_protect_credentials` 保护了它，但列表只列规则包的规则，内置 5 条根本没进去 —— 用户照着列表找找不到责任人。现把内置清单排在最前并标 `(内置保护)`，额外指定标 `(额外指定)`；判定抽出 `matcher_hits` 单条函数与真实判定共用，避免两处漂移 |
| docs/05 用例表无守卫，已漏登 6 条 | 已修 | docs/03、docs/04 都有双向一致性守卫，docs/05 没有，导致「测试清单」慢慢变成旧账。新增 `test_docs_05_test_list_matches_actual`（已实测真红），并补齐漏登的 4 条文档守卫用例 + 2 条 explain 用例 |
| `python -m dirtidy.cli` 静默 exit 0 | 已修 | 没有 `if __name__ == "__main__"` 块时只导入模块、什么都不做却返回成功，容易让人以为命令跑过了。补上该块（标准入口仍是 `python -m dirtidy`） |

### Web 终审闭环（2026-10-10）

审阅页此前只渲染候选与 AI 建议，后端早已返回的 `pending_auto_hits` / `protection` /
`protect_policy` / `quarantine_manifest` **一个都没用上** —— 用户在网页上看不到规则打算
自动隔离什么，也就无法终审，「人工终审」这个核心价值是断的。本轮补齐：

| 项 | 状态 | 说明 |
|----|------|------|
| 网页看不到「规则要动什么」 | 已修 | 审阅页新增「待自动隔离」区块，摆在候选表之前；列出路径、命中规则、类型、原因 |
| 网页看不到「什么被保护了」 | 已修 | 新增「受保护」区块：逐条列出被拦下的路径、保护规则与原因，并显示生效保护策略条数 |
| 网页看不到已隔离项 | 已修 | 新增「已隔离」区块，读 `quarantine_manifest.json` |
| 网页无法执行规则自动隔离 | 已修 | 新增 `POST /api/runs/{id}/apply-rules`；待隔离表每行可勾选「保留」，随请求以 `keep_paths` 提交 |
| 人工保留无处落地 | 已修 | `apply_pending_rules(keep=...)` 与 CLI `apply-rules --keep` 同步支持；保留项本轮不动并记入 `protection.json`（`protect_rule_id=user_kept`）以便审计追溯 |

真机验证：`keep=["app/__pycache__"]` → `quarantined=2, kept_by_user=1`，
`app/__pycache__` 留在原地、`app/node_modules` 与 `old.tmp` 已隔离、密钥与 README 未动。

### 保护清单不可绕过（2026-10-10）

截图审查审阅页时发现两处「不误删」的破口：

| 项 | 状态 | 说明 |
|----|------|------|
| `apply-decisions` 不检查保护清单 | 已修 | `apply-rules` 有保护复核而 `apply-decisions` 没有——后者就成了绕过保护的缝：网页上把 `id_rsa` 标成 quarantine 就能把它搬进隔离区。两条路径的保护语义不一致，本身就是 bug。现共用同一套判定（`_protect_matchers` 读同一份 rules/protect 来源），被拦下的记入 skipped 并写入 `protection.json`（`blocked_at=apply_decisions`）。`archive` **有意不拦**：它是显式指定目标的归类，文件仍在根内可找回，与「清理」语义不冲突 |
| 0 字节文件被判成重复组 | 已修 | 空文件 sha256 天然相同，全被归成一个「内容相同」的组，把 `.env` / `id_rsa` 这类空占位文件混进去，诱导用户点「其余标记隔离」。现 `find_duplicate_groups` 跳过 `size == 0`；空文件自有 `empty_file` 规则处理（进候选） |

真机验证：走 Web 决策路径隔离 `.env` → `blocked_by_protect=1`，原因写明保护规则，文件留在原地；
重复组只剩 `dup_a.txt`/`dup_b.txt` 两个真重复文件。
