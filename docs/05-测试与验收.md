# dirtidy — 测试与验收

本文是验收依据与测试登记表，不是每次运行的测试报告。平台覆盖看 §1，用例与预期看 §3；具体版本是否通过，应查看该次测试输出或 CI 结果。历史测试数量和修复过程收在末尾修订记录，不代表当前总数。

## 1. 平台矩阵

| 平台 | MVP 要求 |
|------|----------|
| macOS | 开发机必测（已跑自动化） |
| Linux | CLI 夹具必测；路径使用 posix 相对路径，与平台无关的用例相同 |
| Windows | 自动化锁定 inventory 路径不含反斜杠；实机 GUI 未在本环境重复 |

三平台由 `.github/workflows/ci.yml` 覆盖（ubuntu / macos / windows × Python 3.11、3.12，
共 6 个矩阵 job），每次 push / PR 跑 `ruff check`、`mypy`、`pytest`。此外有两个**独立 job**：

| job | 验什么 | 为什么单独一个 |
|------|--------|----------------|
| `package` | 真 `python -m build --wheel` → 装进新建 venv → 跑 `dirtidy --version` / `--help` / `load_rule_pack('default')`（24 条）/ 首页与三个静态资源 HTTP 200 | editable 安装走 `src/` 目录，package-data 漏项永远暴露不出来——「本地能跑、装完报缺文件」只在真装 wheel 时才现形（台账 T-14） |
| `smoke` | `python scripts/smoke_e2e.py`（scan → apply-rules → analyze(--mock) → 审计 全流程） | 单测验「零件对不对」，冒烟验「零件装到一起还走不走得通」——接线错误单测最容易漏（台账 T-12） |

## 2. 夹具

`tests/fixtures/sample_workspace/`：

- 含 `node_modules/x`、`__pycache__/y`、空目录、`app.log`
- 含内容相同的两份 `dup_a.txt` / `sub/dup_b.txt`
- 含 `payload.txt` 与将其打成 zip 的 `payload.zip`（成员 hash 应匹配）

其中两样 git 存不下，由 `tests/conftest.py` 在用例开跑前补齐（幂等）：

| 条目 | 为什么 git 存不下 |
|------|------------------|
| `__pycache__/mod.pyc` | 被 `.gitignore` 的 `__pycache__/` 规则屏蔽。那条规则本身是对的，不该为一个夹具放开全局忽略 |
| `empty_dir/` | 空目录，git 根本不能跟踪 |

不补的话症状很隐蔽：开发机磁盘上恰好留着这两样，**本地全绿、CI 全新克隆全红**。
`test_fixture_workspace_survives_fresh_clone` 守着这件事，缺了在本地就红。
