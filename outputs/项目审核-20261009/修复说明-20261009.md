# dirtidy 审核问题修复说明（2026-10-09）

配套文档：`dirtidy-项目审核报告.md`

本次针对审核中**已实证**的缺陷做了修复，并为每条补了回归用例。
验证结果：**33 个用例全绿**（原有 20 → 第一轮 +8 → 第二轮 +5），`ruff` 与 `mypy` 均零告警。

## 一、修复清单

### 1. 路径穿越（P0-1）

**改动**

| 文件 | 改动 |
|------|------|
| `src/dirtidy/models.py` | 新增 `resolve_under(root, rel)`：拒绝绝对路径，用 `os.path.normpath` 做词法归一化（不 follow symlink），断言结果仍在 `root` 前缀内，越界抛 `ValueError`；返回值沿用调用方 root 形态，避免 `/var` 与 `/private/var` 形态差异 |
| `src/dirtidy/decision/store.py` | `apply_decisions` 中 `root / d.path`、`root / target` 全部改走 `resolve_under`；越界条目记入返回值的 `skipped` 明细而非静默执行 |
| `src/dirtidy/quarantine/store.py` | `_safe_dest`、`quarantine_hits` 源路径、`restore_entries` 还原目标全部改走 `resolve_under`；越界条目跳过（还原时保留在清单里） |

**效果**：`path: "../outside/victim.txt"` 不再能把根外文件搬进隔离区；`target_relpath: "../outside/escaped.txt"` 不再能把文件搬出根。

### 2. 凭据摘要泄漏（P1-1）

**改动**（`src/dirtidy/ai/providers.py`）

- 新增 `SENSITIVE_NAME_RE` 文件名黑名单：`credential(s)` / `secret(s)` / `password(s)` / `passwd` / `token(s)` / `api_key` / `id_rsa` / `id_ed25519` / `netrc` / `pgpass` / `htpasswd` / `keystore` / `.env` / `.npmrc` / `.aws` / `.ssh` —— **命中即完全不抽样正文**。用词边界匹配，`tokenizer.py`、`secretary.txt` 这类不会误伤。
- `SECRET_LINE_RE` 扩展为同时覆盖 `key=value`、`key: value`、`"key": "value"`，并纳入 `token|credential|access_key|private_key|auth`。
- 新增 `redact_secrets()`：**把密钥的「值」就地替换为 `***`**。原先的实现是 `text[:200] + 标记`，密钥若在开头 200 字内会**原样留下**——等于没脱敏，这是本次一并修掉的真问题。

**效果**

| 输入 | 修复前 | 修复后 |
|------|--------|--------|
| `credentials.json` | 原样外发 AWS 密钥 | 完全不抽样 |
| `my_secret.txt` | `token=abcdef` 外发 | 完全不抽样 |
| `config.yaml`（`password: hunter2`） | `hunter2` 原样外发 | `password: ***` |
| `app.json`（`"api_key": "sk-live-123"`） | 原样外发 | `{"api_key": "***", "note": "hi"}`（其余保留） |

### 3. 候选为空时全量外发（P1-2）

`analyze_run` 中去掉 `candidates_paths and ...` 短路条件，改为：

```python
if path not in candidates_paths and path.count("/") > max_depth:
    continue
```

并把硬编码深度 `3` 提为 `summary.max_depth` 可配项。
**效果**：`candidates.json` 为空时，深层非候选文件不再外发（实测由 7/7 收敛为 1/7，仅浅层文件）。

### 4. 只读根扫描（P1-3）

| 改动 | 说明 |
|------|------|
| `scanner.py` | 缓存写入包 `try/except OSError`，失败降级为 stderr 警告，不作废已完成的扫描；`_load_hash_cache` 对损坏缓存也降级为空 |
| `models.py` | `state_root()` 支持环境变量 `DIRTIDY_STATE_DIR` 重定位状态目录（默认行为不变），用于只读介质或不愿污染目标目录 |
| `pipeline.py` | 状态目录创建失败时抛出**可操作**的 `PermissionError`，明确提示可设置 `DIRTIDY_STATE_DIR`，而不是裸 traceback |

### 5. 文档与仓库卫生

- `docs/03-架构设计.md` §5 CLI 表：5 条命令补齐 `root` 位置参数，并补充 `DIRTIDY_STATE_DIR` 说明。
- `docs/06`：订正"第一期缺口已补完"的表述，新增「2026-10-09 审核新增待办」表，把已修/未修分开登记。

## 四、第二轮：剩余待办的处理

第一轮遗留的 5 项已处理 3 项并复核 1 项：

### 4.1 前端 XSS（已修）

| 文件 | 改动 |
|------|------|
| `src/dirtidy/web/static/app.js` | 新增 `el()` 辅助函数；**全面移除 `innerHTML`**，文件名/路径一律走 `textContent` 或 `setAttribute`；重复组的 radio 选择器改用 `CSS.escape()` |
| `src/dirtidy/web/app.py` | 新增安全响应头中间件：严格 CSP（`default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self' data:; base-uri 'none'; form-action 'none'`）、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer` |

实测 `/` 返回 200 且三个响应头均正确下发。另加静态守护用例 `test_frontend_avoids_innerhtml`，`app.js` 一旦再用 `innerHTML` 测试即红。

### 4.2 `package_root()` 依赖 editable 安装（已修）

`load_model_config` 改为按优先级查找，不再依赖「包位于源码树中」：

1. 显式 `--config` 路径 → 2. `$DIRTIDY_CONFIG` → 3. `./models.yaml` → 4. `~/.config/dirtidy/models.yaml` → 5. `<项目>/configs/models.yaml`（仅 editable 开发时存在，兜底）

找不到时报错并列出全部已查找位置，仍不静默回退到 `models.example.yaml`。新增 3 条用例覆盖显式路径 / 环境变量 / 用户配置目录三种入口。

### 4.3 CI 与工具链（已修）

- 新增 `.github/workflows/ci.yml`：ubuntu / macos / windows × Python 3.11、3.12，跑 `ruff check` → `mypy` → `pytest`。
- `pyproject.toml` 新增 `[tool.ruff]`（`line-length = 120`，`select = ["E","F","W","I","UP","B"]`）与 `[tool.mypy]`。
- 为让两项静态检查真正零告警，顺带修了 4 处类型/风格问题：`models.py` 用 `datetime.UTC`、`rules/engine.py` 变量复用导致的类型冲突、`hashing/content.py` 的 `tarfile` mode 字面量类型、`decision/store.py` 的 `save_decisions` 参数改 `Sequence`（协变）。
- **本机实测**：`ruff` → All checks passed；`mypy` → no issues found in 21 source files。

### 4.4 `httpx2` 复核结论（已移除）

复核发现：`httpx2` 是 pydantic 维护的真实包（`httpx` 的下一代），但**代码中零引用**（`src/` 只用 `httpx`），且 `docs/06` 原记的「Starlette 渐弃用警告」在 `pytest -W error` 全量复测下**已不再复现**。故从 `dev` 依赖移除，改为 `pytest` + `ruff` + `mypy`。

### 4.5 空 `apps/` 骨架（已删除）

确认 `apps/web/static/` 下 **0 个文件**、git 未跟踪（空目录本就不入库）、全仓无任何引用，用 `rmdir` 删除（`rmdir` 遇非空目录会拒绝，天然安全）。
