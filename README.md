# dirtidy

单机、单用户的本地目录整理工具：规则找出可隔离项，可选模型辅助分析，最后通过本地网页或命令行确认执行。

默认只扫描和生成候选；执行隔离后，文件移入隔离区，可以还原。只有明确彻底删除，或事先开启某条规则的直删开关，才会物理删除文件。

## 安装

需要 Python 3.11 或更高版本。在仓库目录运行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
source .venv/bin/activate
dirtidy --version
```

以下命令假设虚拟环境已激活。也可以直接用 `.venv/bin/dirtidy`；Windows 使用 `.venv\Scripts\dirtidy.exe`。

## 开始整理

首次使用建议选可恢复的测试目录，把下面路径换成实际目录：

```bash
dirtidy start /path/to/root
```

没有扫描结果时先扫描，然后打开本地网页，不移动待整理文件。已有结果时直接打开；重新扫描加 `--rescan`。

在网页按顺序操作：

1. **审阅**：看路径、占用和恢复方式，不想动的明确设为保留。
2. **执行**：先预览完整清单，再确认隔离或归档。
3. **隔离区**：验证还原。确定不需要的副本再彻底删除。

筛选只改变列表显示，**不会缩小执行范围**。首次使用保持直删开关关闭；隔离副本仍占磁盘空间，彻底删除后才释放。

完整步骤、手动验证方法和参数查阅见 [使用手册](docs/09-功能与使用汇总.md)。

## 常用命令

只扫描，不搬文件：

```bash
dirtidy scan /path/to/root
```

查看判定原因，或只预览本轮规则隔离计划（替换实际的 `run_id`）：

```bash
dirtidy explain /path/to/root node_modules
dirtidy apply-rules /path/to/root <run_id> --dry-run
```

定时扫描，不执行隔离：

```bash
dirtidy watch /path/to/root --interval 30
```

模型分析不是必需步骤，默认关闭。接入与外发范围见使用手册第 2.2 节。

## Cursor 旧会话清理

`cursor-cleanup` 是独立命令，不走目录隔离区。先完全退出 Cursor，再只读预览：

```bash
dirtidy cursor-cleanup --days 90 --measure
```

它仅选择有时间证据且超过 90 天的会话；近期活动与时间未知的孤儿会话保留，共享 blob 不删除。候选行字节估算不等于最终可释放空间。

执行会删除选中的历史会话，需要明确加 `--apply`。备份、验证步骤与限制见使用手册第 2.4 节；不要将它视为全数据无损清理。

## 安全与限制

- 内置保护覆盖版本控制元数据、凭据与密钥等；命中隔离的目录若包含受保护后代，也会整条拦下。额外保护可用 `--protect`。
- 隔离前复核保护与人工保留。开启直删的条目不可还原，网页与 CLI 沿用同一份直删设置。
- 模型默认不发正文，但摘要仍可能含路径等信息。网页直接填写的密钥会明文落盘，建议使用环境变量。
- 状态与审计默认写到 `<root>/.dirtidy/`；可用 `DIRTIDY_STATE_DIR` 改到外部可写目录。
- 不要同时运行多个进程处理同一个目标目录。硬杀进程或内存耗尽时，最后搬移的记录可能来不及写入清单。
- 本地网页没有鉴权，默认监听 `127.0.0.1`，不要暴露到公网。
